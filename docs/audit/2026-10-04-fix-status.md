## Итоговый прогон на одноразовом PostgreSQL 16

- `node --check` по `server.js`, `lib`, `db`, `scripts`: ошибок нет.
- `npm run test:unit`: 28 из 28.
- `npm run test:integration`: 12 из 12 (отдельная база `team_health_itest`).
- `npm run build`: зелёная.
- Playwright на новом сервере: 18 из 18, дважды подряд на одном процессе.
- `docker compose config` для профилей по умолчанию, `prod`, `test`: валидны.

Единичные красные прогоны объяснены: Postgres в песочнице однажды остановился между шагами (перезапущен); один набор UI-тестов упал из-за лимита входа 429 после десятка повторных прогонов на одном процессе (лимит в памяти, после рестарта сервера всё зелёное; отражено в `docs/qa-brief.md`); тест смены пароля предполагал две параллельные сессии, а продукт оставляет одну сессию на пользователя (исправлен тест, не продукт); моя проверка на «старом коде» один раз была недействительной, потому что убила базовый сервер, и была повторена на живом.

## Что не проверено

- Сборка Docker-образов: демона Docker в песочнице нет. `compose config` валиден, runtime-образ эмулирован копированием файлов и запуском в production.
- GitHub CI: ветка не вливалась и PR не создавался, поэтому workflow не запускались. YAML синтаксически валиден, шаги проверены по отдельности локально, кроме `upload-artifact` и `gitleaks`.
- Поведение за реальным прокси Railway (`TRUSTED_PROXY_HOPS=1` предполагает один прокси) и реальная работа `healthcheckPath=/readyz`.
- Визуальная проверка стилей, баннера конфликта и подтверждений глазами; контраст посчитан формулой.
- Живой продукт, TLS, заголовки на домене: продукт выключен.
